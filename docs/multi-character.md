# 多角色模式

[返回素材库教程](libraries.md)

本文对应 0.26.15 正式版（2026-11-18）。

## 先准备人物

1. 在「角色档案」新建人物，填写固定外貌、服装并保存。
2. 名称之外的称呼填到「人物别名」，用 `|` 分隔，例如 `阿蓝 | Blue`。
3. 在「出场人物」勾选本次可用的人物。聊天覆盖只影响当前聊天，全局档案可反复使用。
4. 在「出场方式」中选「随剧情出场」或「固定出场」。

「随剧情出场」允许助手为每一张图单独筛选人物，只是提到名字或回忆人物不要求其入画。「固定出场」要求助手每张图保留此人。助手结果中的「本图出场人物」可以再手动勾选；固定人物需先到档案里调整出场方式。

直接手动生图且没有使用助手或分段提示词时，使用已经勾选的全部人物，不额外调用文字模型来猜测谁该出现。漫画每格继续以「本格出场角色」为准。

## 位置与互动

「画面位置」可选择常用方位，也可展开 5×5「位置网格」点击坐标。A 在最左、E 在最右，1 在最上、5 在最下；例如 B3 为偏左中部，D3 为偏右中部。「并排站位」会为多个人物分配位置，人数较多时分行安排；箭头按钮交换站位，恢复按钮取消指定坐标。

「人物互动」先选对象，再选择由本角色发起或双方共同动作，最后填英文动作标签，例如 `hugging`。目标人物没有出场时不会提交该互动。

NovelAI 原生角色接口会使用角色坐标和互动标签；通用图片接口会把人物和互动整理成文字描述，位置准确度取决于模型。原生坐标模式下，只要有人手动指定位置，就会开启全图坐标；同图仍选自动的人物按中央提交，预览会提示。

漫画分镜中可分别设置「本格位置」和「本格互动」。未指定本格位置时跟随项目站位，明确选择的本格位置优先。互动可选「跟随项目互动」或「无本格互动」，也可以为本格指定其他对象与动作；这些修改保存在该分镜，不改全局档案。

## 聊天里的分段提示词

把以下内容放进已经设置好的聊天生图提示词块中：

```text
Scene Composition: 2girls, cafe, afternoon light;
Character 1 Name: 阿蓝;
Character 1 Prompt: blue hair, blue eyes;
Character 1 Action: holding a cup;
Character 1 Expression: smiling;
Character 1 UC: red hair;
Character 2 Name: 旅人;
Character 2 Prompt: green hair, white dress, reading |centers:D3;
Character 2 UC: bad hands;
Negative prompt: blurry, lowres
```

「Scene Composition」是公共场景，每个「Character N」是一名人物的描述和负面词。可以用分号或换行分隔，不要求末尾分号。也支持「场景描述」「角色1名字」「角色1正向提示词」「角色1动作」「角色1表情」「角色1服装」「角色1负面」「全局负面」。

名称与别名按完整名称或完整标签匹配，不按子串猜测。同名档案有歧义时保留为本图临时角色，并在预览中提示；可以用 `Character 1 ID: 档案ID` 明确指定。没有匹配的角色只属于本图，不会自动写入档案库。重复编号字段、缺少人物正向词或人数超限会提示修正。

也兼容在角色 Prompt 末尾附加 `|name:阿蓝`、`|id:档案ID`、`|centers:B3`。已手动指定的档案站位优先于分段坐标。

外貌锁定时使用档案里的固定特征。旧式 Prompt 混写的 `waving`、`smiling` 等可识别动作表情会保留；无法可靠分类的描述不会覆盖锁定外貌。为确保任意动作都生效，建议明确填写 `Action`、`Expression`。`Outfit` 只在服装未锁定时使用；固定服装仍以档案或已应用换装为准。

普通提示词没有角色分段时按原流程处理，不要求改写世界书。

## 先预览再生图

在生图工坊点「预览本次生图」查看：

- 合并后的公共正向词、全局负面词与画师风格。
- 本图每个人物的实际正向词、负面词和位置。
- 当前采用独立角色参数，还是合并文字描述。
- 名称歧义、外貌锁定、站位重叠、互动信息不完整和混用自动／手动坐标等提示。

预览不提交文字或图片请求。修改档案、模型或参数后，重新预览再提交。

## 载入旧图后调整人物

从绘图管理载入带人物记录的图片参数后，「出场人物」显示「本次人物配置 · 与档案库独立」。此时修改动作、站位、互动或出场名单只影响当前参数，不会写回全局或聊天档案。旧图中已删除、停用的档案显示为「图片记录」，仍可取消出场。

把所有角色取消后，会明确显示「本次未附加角色档案」，刷新或再次载入参数不会自动补回档案库的人物。这里只是不附加角色档案；公共提示词中仍可包含人物描述。

清空动作、表情或恢复自动站位，会同时清除旧图保存的对应助手指令。选择「使用当前档案」可结束本次独立调整，回到当前聊天或全局的出场配置。包含临时服装时，对应按钮为「清除本次人物调整」。

## 第一次创建角色

在生图工坊没有角色档案时，可点「创建角色档案」或「AI 创建档案」。当前聊天没有可覆盖的档案时，「创建全局档案」会直接切到新建表单。

填好外貌后，点「保存并加入出场」即可保存档案，并将人物加入当前聊天或工坊的出场名单；「仅保存档案」只存入档案库。已选人物的站位、服装和动作不会因为再次保存被重置。达到模型人数上限时，可先仅保存档案，再调整出场名单。

切换角色、档案范围或画师串时，未保存修改使用主题内确认窗口，默认继续编辑。取消不会丢失草稿，也不会让浏览器陷入原生确认框。

## 聊天图片再画

| 操作 | 公共画风 | 人物来源 |
| --- | --- | --- |
| 再画一张 | 当前预设正向前缀、画师串、负面词 | 原图记录的人物与动作 |
| 更多 → 沿用原图画风再画一张 | 原图画风 | 原图记录 |
| 更多 → 使用当前档案与画风再画 | 当前画风 | 按原图人物 ID 读取当前档案与服装，保留本图动作、位置 |

第三种操作只更新原图已有的人物，不会把其他聊天的人物追加进来。已删除或停用的档案继续使用原图记录。旧图片没有保存分项动作时，只能恢复可识别的动作表情；复杂动作可在重新生成前手动补充。已有图片和历史版本保持各自的生成快照。

## OpenAI 兼容的 NAI 模型

默认使用「合并描述 · 通用兼容」。只有接口提供方确认支持时，才在生图工坊选择「独立角色 · v4_prompt 格式」或「独立角色 · characterPrompts 格式」。

这两个选项分别在图片请求顶层发送对应字段，不代表所有中转都接受，也不会自动尝试不同格式或重复计费请求。若接口要求把这些字段放到其他结构中，应保持默认方式，或按接口文档另行适配。

如果使用可选的「酒馆服务器」组件保存助手聊天草稿，应同步更新到组件 0.21.3／协议 2，才能在刷新、恢复后完整保留新加入的每图人物名单、位置和互动字段。由管理员覆盖组件代码、保留账号限制和数据后重启酒馆。普通账号存图无需额外组件。本地图片快照、档案库和漫画项目使用前端归一化与保存逻辑。
