# 聊天联动与提示词助手

[返回教程目录](../README.md)

0.26.0 的入门流程、底层规则编辑、预算设置和失败恢复，见 [提示词助手图文教程](preview/assistant.md)。

聊天联动有两条路径：识别回复里已经写好的提示词，或由文字助手先分析画面再准备提示词。两者共用图片接口与任务队列。

## 标签生图

默认格式：

```text
角色推开窗户。image###1girl, opening a window, morning light, anime illustration###
```

1. 在角色设定、系统提示或你使用的酒馆预设里，约定让模型按这个格式写画面提示词。
2. 配好图片接口，启用插件设置中的「自动生图」。
3. 等角色新回复完整结束。插件识别标签后，将其保存为关联该会话、消息和回复分支的任务。
4. 「生成前确认提示词」开启时先核对草稿，关闭时直接入队。
5. 生成期间显示主题小人和阶段，成功后在原标签位置显示图片。

同一条消息可有多个标签，每个标签分别关联图片。不会自动绘制用户消息、尚未完成的流式片段或打开时的历史消息。只更改触发格式设置不会自动修改你的酒馆提示词。

关闭「在聊天中显示图片」只恢复标签原文，作品仍在绘图管理。关闭插件也会恢复原文；再次开启或刷新后可按已有记录恢复显示。

## 手动给一条回复配图

点击角色回复上的「给这条配图」：

- 已有标签：选择尚未生成的标签，提交绘图。
- 没有标签：先准备智能配图草稿，检查画面与提示词，再决定是否绘图。

手动入口可以处理旧消息。插件不会因为刷新而自动补画整段历史，避免重复提交。

## 聊天图片快捷操作

| 操作 | 结果 |
| --- | --- |
| 点击图片 | 打开大图、参数与历史版本。 |
| 再画一张 | 沿用本图参数，用新随机种子重新采样，保存为同图组的新版本。 |
| 修改提示词 | 修改本图的正向／支持的负面词后重画，不改全局提示词。 |
| 收藏、下载 | 收藏作品，或下载原图。 |
| 更多菜单 | 复制提示词、导入参数、完整编辑、图生图、局部重绘、图片增强或绘图管理。 |

无种子参数的 OpenAI 模型按原参数重新采样；ComfyUI 随机重画需要种子映射。重画期间旧图保留，可在聊天内切回旧版本。完整编辑类操作需要当前存储位置能访问原图。

## 提示词助手

入口：「提示词助手」。

1. 配好下方的文字模型来源。
2. 在「输入描述或提示词」写中文画面，或点「读取当前提示词」。
3. 选提示词模板及英文标签／英文自然语言等输出格式。
4. 点「生成提示词」「翻译」或「润色」。
5. 检查生成的画面、正向、负面和角色信息，可继续手动编辑。
6. 「载入生图参数」只填参数；「生成图片」才进入图片任务。

模型可能理解错误，生成后的草稿可以先用中文标签库或可视化编辑修正。界面说明无需配图时，也可核对理由后手动调整。

### 跟随酒馆

使用酒馆当前文字接口和采样配置。文字模型留空时跟随当前模型；可点刷新获取可用模型，独立选一个用于助手，不改变酒馆正文模型。

独立选模需要酒馆聊天补全接口支持；不提供模型查询的来源会尽量读取酒馆现有选项。正文正在生成时，先等待结束再使用跟随助手。

### 独立 API

填写 OpenAI 兼容文字接口地址、Key 和文字模型。接受根地址、带或不带 `/v1`、末尾 `/` 及支持的完整接口地址。

「连接方式」可选择：

- **设备直连**：默认方式，由当前浏览器访问接口，需要接口允许浏览器跨域访问，设备代理也需覆盖该域名。
- **酒馆转发**：浏览器先请求酒馆，再由酒馆连接独立 API。继续使用助手填写的地址、Key、模型、温度和输出上限，不更换酒馆正文接口、模型或已保存的秘钥。模型列表、分析、翻译、润色、创建角色档和单图重分析共用该路线。

跟随酒馆可用、独立直连失败时，可以尝试「酒馆转发」。酒馆所在设备或服务器必须能访问上游接口；手机代理不会自动作用于远程酒馆。转发会将本次请求的密钥交给自己的酒馆服务器使用，无需另装增强组件。设计预览不支持酒馆转发。

连接失败时点击配置旁的「检测助手网络」，完成后复制脱敏日志给作者。也可在「调试工具 → 网络检测接口」选择「提示词助手 · 独立 API」。检测使用当前连接方式，只读取模型列表，不提交文字生成。转发日志标记 `scope: tavern-relay`，其中 HTTP 状态属于酒馆入口；部分宿主隐藏上游状态码，入口返回 200 不代表上游鉴权通过。

独立文字 API 可自动继承「接口配置」里的 OpenAI 图片连接；图片连接尚未配置时，也可用已填写的独立文字连接补齐。地址与 Key 成对同步，两边原本已有不同配置时保留各自设置。文字模型和图片模型分别选择，接口共用不等于模型共用。

点「获取文字模型列表」，再通过「选择文字模型」展开列表。可搜索后直接点选，手机端不再依赖浏览器输入框的候选弹层。接口未提供模型查询时，可直接在「文字模型」输入准确模型名。

读取失败会在模型旁显示原因，保留已经填写的模型与 Key，不自动重复请求。修改地址、Key、连接方式或模型来源会取消旧列表查询。正常后台任务同步不会替换正在编辑的助手表单。

最大输出 Token 默认 **4000**，界面可调整至 **256～131072**；实际仍受接口和模型限制。可按接口与模型保存兼容参数及预算；另有温度与超时设置。请求失败不会自动切换路线重试。

## 智能配图

手动可点击「当前消息配图」，或在无标签的回复上点「给这条配图」。

助手读取截至目标消息的最近聊天；可选择参考角色卡、世界书和固定外貌，按设定的消息数与字符上限准备画面。世界书使用酒馆的相关条目扫描，插件不修改聊天正文。

流程是：读取上下文 → 判断画面 → 返回画面与英文提示词 → 人工检查／保存草稿 → 提交图片任务。多角色外貌和服装可来自角色档案。

自动化有两个独立开关，默认都关闭：

| 开关 | 开启后的行为 |
| --- | --- |
| 自动准备配图提示词 | 在新完成的角色回复后调用文字助手，准备画面草稿。 |
| 准备后自动生图 | 草稿准备好且符合配图条件后，继续提交图片生成。 |

推荐先只开启自动准备，检查一段时间的草稿质量，再决定是否自动生成。还可选按剧情判断、每条新回复或每隔几条回复，设置特写／全身／环境、张数和画幅。

已有生图标签的消息继续走标签流程。自动配图不补画问候、历史消息或被停止的回复；草稿和“不配图”的判断会记录，刷新不自动重新调用文字模型。

## 消息变化与取消

切换聊天、改原文或换回复分支后，尚未提交的聊天生图会取消。已被图片服务接收的任务继续取图和保存，回到原会话和分支后可显示对应结果。

助手失败或超时不自动重试。跟随酒馆的某些请求取消后只丢弃结果，底层文字请求可能继续完成；不会调用酒馆的全局停止去影响正文。任务恢复见 [绘图管理与任务](gallery-tasks.md)。
# 助手工作流补充

- **每条回复规划画面数**：默认 1，可设为 2 至 4。助手一次分析多个画面，分别返回提示词和原文定位句。定位句必须是当前回复中的原句；没有唯一匹配时，图片放在消息末尾。
- **每个画面生图张数**：表示同一个画面的图片数量，与规划画面数分别计算。例如 2 个画面、每个画面 1 张，会提交 2 个独立生图任务。
- 多图草稿可通过“画面 1 / 画面 2”等标签分别编辑、复制、载入参数或生成；关联聊天时还可以点击“生成全部配图”。每个画面拥有独立任务记录，刷新后不会自动重新提交。
- **记录动态角色状态**：默认关闭。开启后，助手在同一次分析中提取剧情明确说明的外貌、服装、动作、表情变化，并附上原文依据，保存到该聊天消息的扩展数据中。后续配图参考此前状态；编辑原消息或切换回复分支后，不读取失效状态。固定外貌与服装锁定继续优先。
- 可在“当前聊天的角色状态”中读取或清除记录。状态跟随聊天保存，不修改角色卡或全局角色档；保存失败会显示提示，不影响已经得到的配图草稿。
- **任务消息模板**：可分别配置生成、翻译、润色、聊天配图、创建角色档、单图编辑的消息角色和顺序。每个任务最多 16 条。保留且仅保留一处 system 消息中的 `{{rules}}` 和一处 user 消息中的 `{{input}}`，分别代表内置任务规则和输入资料；可在前后加入自定义要求或示例。
- 酒馆预设仍按原生列表顺序放在任务消息之前；“跟随当前酒馆预设”仍读取全部已开启的可发送文字条目。
- **返回方式**：默认“普通 JSON 回复”。接口明确支持时，可选择“接口 JSON 模式”或“工具调用”。不支持时请切回默认模式；插件不会因协议报错自动重复计费请求。

## 助手调用诊断

在助手页展开“助手调用诊断”，可查看当前页面最近 8 次文字调用。记录包含实际提交的文字模型、跟随酒馆或独立 API、返回协议、各阶段耗时，以及本次真正发送的酒馆预设条目顺序。未提交模型请求便失败时，会显示“尚未提交”或未取得模型标识。

“预览当前请求”只组装当前配置，不调用模型；“查看失败回复”展示本页保留的最近失败原文。独立 API 可直接打开已有的设备网络检测。

“复制脱敏诊断”不会包含秘钥、认证头、聊天正文、提示词、模型回复、预设名称和接口路径。诊断仅保留在当前页面，刷新即清除，不进入设置或备份。跟随酒馆的原生请求不一定提供 HTTP 状态，诊断不会为此额外发送测试或重试请求。

## 助手方案库

助手配置顶部有“日常配图”“人物特写”“多图剧情”三个内置方案。载入内置方案只调整构图、画幅和张数，保留当前接口、秘钥、模型、酒馆预设和自动化开关。

填写方案名称后点击“另存为方案”，保存当前完整助手配置；选中自己的方案后可载入、更新或删除。自建方案包含接口来源、模型、酒馆预设选择、上下文上限、返回方式、各任务消息模板及自动配图设置。载入前请核对列表下的自动生图状态。方案最多 30 项，总容量 400 KB。

自建方案的秘钥通过本机凭据库引用保存，与之后编辑的当前接口分开。普通方案导出不含秘钥和本机凭据引用；导入后需要核对地址并填写秘钥。完整个人加密备份可连同方案秘钥一起备份。导入无效或超出限制的方案文件时，整次导入取消，已有方案保留。

## 提示词检查

在画面草稿下点击“检查当前画面”，检查重复的普通标签、正负向重叠、可能冲突的发色或瞳色、缺失的已选角色条目，以及原文定位句是否唯一匹配。多图草稿按当前选中的画面检查。

点击对应按钮才能去重、清除无效定位句或补回角色条目；这些操作不调用文字模型，也不提交图片生成。带权重、嵌套组、LoRA 等复杂写法保持原样。配色冲突和正负重叠仅提醒手动核对，渐变发色或多角色场景会减少不确定的颜色提醒。

修改草稿后需重新检查，避免把旧检查结果应用到新内容；支持撤销上一次修正。原文不可读取时只标记定位句“尚未核对”，不会猜测新定位句。无效定位句仍会安全回退到聊天消息末尾显示图片。

## 草稿历史与对比

在“草稿历史”中可选填版本名称，再点击“保存当前版本”。每次分析成功替换草稿时，助手也会保留替换前的手动修改和新的结果；从聊天打开另一份草稿时同样会先保留当前内容。

历史按当前账号保存，刷新后仍可读取。最多保留 12 个版本，总容量 600 KB，达到限制时移除较旧记录。历史使用独立账号字段和浏览器缓存，只在版本变化时同步；旧版历史会自动迁移。单份草稿超过历史容量时会显示提示，工作草稿仍然保留。历史记录包含画面、正负提示词、角色快照、输入描述和所选画面，不记录接口配置、秘钥或原聊天绑定。

选择版本后点击“对比当前草稿”，按画面列出正负提示词、构图、角色及定位句等变化。左侧是历史版本，右侧是当前草稿；手机上改为上下排列。超长字段预览前 8000 字符，恢复仍使用完整内容。编辑当前草稿后需点击“刷新版本对比”查看新差异。

“恢复为独立草稿”会先保留恢复前内容，再恢复该版本的整组画面和选中位置，不改变当前接口或自动化开关。恢复结果不关联旧聊天，不自动生成图片；核对后可点击“载入生图参数”或“生成图片”。可删除不再需要的单个历史版本。

历史属于工作草稿数据，与当前输入、失败回复一样，不包含在配置备份和共享方案中。

## 手动修复失败回复

模型返回了文字但 JSON 缺失、截断或格式不正确时，展开“查看最近失败的模型回复”，点击“手动修复回复”：

1. 在编辑框中修正完整 JSON，可删除额外说明、修正括号和字段；原始失败回复仍保留在上方。
2. 点击“解析修复内容”，本地检查结构、正负提示词长度、画面数和多图定位句，并展示预览。不会调用文字或图片接口，也不会猜测缺失内容。
3. 核对预览后点击“采用修复草稿”。当前工作草稿先进入历史，修复结果作为独立草稿供继续编辑和生成。

修复后的角色快照只使用本次分析时本机选中的角色，模型返回的角色锁定、绑定或参考图信息不会被采用。不会把修复结果写回旧聊天或记录动态角色状态。预览期间若工作草稿发生变化，需要重新解析再采用，避免覆盖新修改。

失败原文和修复编辑只保留在当前页面，刷新或开始下一次分析后清除；采用后的工作草稿和历史照常保存。网络或鉴权失败没有模型正文时，不提供回复修复。

## 单画面重分析

在画面结果下展开“单画面重分析”，先选择需要调整的画面，再填写修改要求，例如“保留人物，镜头拉近，改成雨夜窗边”。勾选需要保留的字段，点击“重新分析此画面”。

助手只请求一个画面结果。默认保留原文定位句，也可保留正负提示词、画幅、画面描述或角色动作与服装；角色档的外貌和服装锁定始终有效。

结果先显示字段差异，点击“采用此画面修改”才替换当前画面；其他画面保持原样，替换前草稿进入历史。采用不自动生图，不写入动态角色状态。点击“放弃修改”可丢弃预览。

分析或预览期间若修改了草稿、模型设置、上下文选择，切换聊天、编辑原文或更换回复分支，需要重新分析。取消文字请求不会覆盖当前草稿。

## 上下文选择与用量

在上下文设置中展开“上下文选择与用量”，点击“读取聊天上下文”。默认仍按“最近消息数”自动选择，可在最近 80 条可用消息中手动勾选最多 40 条，点击“恢复自动选择”回到默认。手动选择只用于当前聊天页面，刷新或切换聊天后恢复自动选择；自动配图继续使用自动上下文。

每条消息显示实际纳入与原始字符数，展开“实际纳入的聊天内容”可查看本次提取的正文。聊天超过字符上限时保留较新的内容；较早消息可能被截断或完全省略。当前目标回复另行作为 TARGET 提供，最长 32000 字符，因此取消勾选目标回复的历史副本不等于取消目标本身。角色卡与世界书的截断也会显示。

点击“预览完整请求”可检查完整消息以及估算输入 Token，不调用模型；完成分析后面板也会显示实际组装请求的输入估算与最大输出。估算按字符计算，实际计费与模型上下文限制以接口为准。所有启用的酒馆预设文字仍按原顺序完整发送，不为节省用量自动删除或截断预设。

消息编辑、删除或换分支后，手动选择会提示重新读取，避免把旧选择误用于新内容。助手输入采用短暂合并保存，开始模型请求、切换页面或离开页面时会补存最新编辑。

## 校正当前聊天的角色状态

在提示词助手中展开“当前聊天的角色状态”，点击“读取状态”。每个非空字段显示来源消息序号及原文引用；跨消息继承的服装、动作等分别显示各自的出处。

点击角色旁的铅笔可修改外貌、服装、动作、表情，再点击“保存状态校正”。清空某个输入框会清除该字段，不再从较早记录补回来。人工修改显示“手动校正”，不把旧原文当作修改后内容的依据。角色档的外貌、服装锁定仍然优先。

垃圾桶只移除对应角色的当前状态；“撤销上次状态修改”可撤销本页面最近一次校正或移除。重新读取不会丢失撤销机会，刷新页面后不保留撤销记录。聊天或状态变化后，旧撤销不可用；“清除状态”删除当前聊天全部状态，不提供撤销。

状态保存在当前聊天消息的扩展数据中，刷新后仍可读取，不修改角色卡、全局角色档或聊天正文。修改来源原文、删除消息或切换回复分支后，依赖这些内容的校正快照失效；编辑期间发生变化时需重新读取。后续新消息中明确提取的变化可继续更新状态。启用“记录动态角色状态”后，后续配图才会参考这些记录。

## 分享任务消息模板

“任务消息模板”在输入时即时检查必要占位符的数量和消息类型；校验失败时对应任务不能发送，需先修正。必须保留一处 system 消息中的 `{{rules}}` 和一处 user 消息中的 `{{input}}`。其他酒馆宏保持原样。

点击下载图标导出六类任务的当前模板，没有自定义的任务使用默认消息。文件只包含任务消息、角色与顺序，不包含接口地址、秘钥、模型、酒馆预设或自动生图开关；自定义消息正文由用户自行填写，分享前请展开核对其中的内容。

点击上传图标选择模板 JSON，先查看任务清单和完整消息内容，再点击“应用导入模板”。导入文件中的任务替换同名任务，未包含的任务保留；预览后又修改了模板时，需要重新导入。取消预览不会更改配置。

文件上限 400 KB，六类任务总内容最多 96000 字符，每个任务最多 16 条消息、单条最多 8000 字符。未知任务、额外配置字段、错误占位符或超限内容都会取消整次导入。
