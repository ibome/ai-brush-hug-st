# 接口配置与预设

[返回教程目录](../README.md)

入口：「插件设置」选择模式，再到「接口配置」。参数预设位于页面上方，便于先选配置再填写。秘钥框旁的眼睛按钮可显示／隐藏本次输入。

## 连接失败时检测设备网络

「测试连接」失败后，旁边会显示「打开调试工具」。进入后选择接口并点击「检测当前设备网络」。请在出问题的手机或电脑上检测，工具使用当前浏览器的网络；不由作者的电脑或酒馆服务器代测。

1. 等待各项检查完成，或点击「停止检测」保留已有结果。
2. 查看 HTTP 状态、耗时和检查结果，再点击「复制诊断日志」发送给作者。也可下载文本日志。
3. 若浏览器禁止自动复制，展开的日志会被选中，可长按复制。
4. 修改代理模式或网络后，关闭面板并重新测试连接；仍然失败时再次检测，对比日志。

官方 NovelAI 分别检查 `api.novelai.net` 账号接口和 `image.novelai.net` 图片域名。OpenAI 兼容、ComfyUI、SDWebUI 使用各自只读列表或信息接口。没有已知只读鉴权入口的第三方只检测服务访问，不发送秘钥；检测不提交生图、文字生成或工作流任务。

日志记录插件版本、浏览器与系统标识、在线提示、页面协议、脱敏域名、请求 HTTP 状态和耗时；隐藏秘钥、认证头、账号密码、自定义路径和查询参数，不包含接口响应正文、模型列表、聊天或提示词。日志不自动上传，关闭页面后不保存在账号配置中。

浏览器常把 DNS、TLS、代理、跨域、重定向与拦截统一表现为请求失败，插件不能强行分辨。不透明响应只作辅助信号，不能确认 HTTP 状态、跨域或鉴权；HTTP 请求成功也不表示生图权限已验证。代理是否开启、是否命中分流规则仍需用户或管理员核对。

## NovelAI

1. 选择 NovelAI，填写自己的 API Key。
2. 官方 `pst-` 秘钥直接使用官方图片接口。第三方地址留空时，会尝试识别已适配的蛋糕生图、砂糖绘画；砂糖还支持 `STD-` 秘钥。
3. 其他第三方服务展开「第三方接口地址（可选）」填写根地址。`pst-` 仍始终走官方接口。
4. 点击「测试连接」，核对界面识别的服务与连接信息。
5. 选择模型。默认 `nai-diffusion-4-5-full`，再设置画师串、正向、负面、尺寸和步数。
6. 到生图工坊实际生成一张，确认权限后另存为预设。

`sk-` 只是常见秘钥格式，不能由这个前缀判断所有服务的地址。自动识别只适用于已适配项目；服务未识别时应填写其地址。

其他参数包括采样器、噪声调度、提示词引导、种子、张数、质量词和负面预设，界面会按模型能力开放。开始时先用默认参数，只改提示词和尺寸，确认可用后再逐项调整。

## OpenAI 兼容

1. 填接口地址和 Key，例如 `https://example.com` 或 `https://example.com/v1/`。
2. 默认生图路径为 `/images/generations`，特殊代理可在「连接选项」修改。
3. 点击「获取列表」，展开列表后可搜索、选择或复制完整模型名；也可直接手填。
4. 选择实际支持图片生成的模型，填写提示词、尺寸、张数和质量。
5. 首次用一张小图验证，再保存预设。

根地址支持带或不带 `/v1`、带或不带末尾 `/`。服务若部署在子路径下，应保留那个代理前缀。可以查看生图请求，核对最终 URL 和参数。

模型列表可能同时返回文字模型与图片模型。**列表能获取，只表示列举模型的请求成功，不能保证列表中每个模型都能生图。**

### 通过 OpenAI 格式使用 NAI

当模型名包含 `nai-diffusion` 时，界面显示独立负面提示词输入框。例如服务返回 `nai-diffusion-4-5-full`，直接选它，然后分别填正向与负面词，不需要手动添加模型名前缀。

第三方对种子、尺寸和其他参数的支持取决于其实现。额外参数可填写 JSON，例如 `{"seed": 12345}`；不要把凭据放入附加参数。

普通图片模型没有通用的原生负面词字段。使用自然语言描述希望排除的内容，或让提示词助手整理；不要照搬 NAI 的参数名。

### 图片编辑

服务明确支持 OpenAI 图片编辑时，在「高级生图」开启「此接口支持图片编辑」，再使用参考图、底图或蒙版。默认图片编辑路径为 `/images/edits`，按 multipart 传图。

普通图片生成成功不代表图片编辑也可用。包含 `nai-diffusion` 的模型不会被假定支持 OpenAI 图片编辑。模型相关的输出格式、透明背景、压缩等选项也要以服务能力为准。

## ComfyUI

1. 填 ComfyUI 服务根地址；需要时在认证选项配置 Bearer 令牌。
2. 点击「测试连接」，读取服务信息和节点／模型列表。
3. 在 ComfyUI 中把已测试可运行的工作流导出为 **API 格式 JSON**，到灵画师导入。普通界面布局 JSON 与 API 请求工作流不是同一格式。
4. 展开「节点映射」，把正向、负面、宽高、种子、步数、CFG、批量、模型等对应到实际节点输入。
5. 指定结果输出节点；不指定时读取可用图片输出。
6. 回到基础参数填写已映射的字段，生成一张验证后保存工作流预设。

未映射字段会禁用，含义是保留工作流原值。插件不能仅根据一个输入框推断复杂工作流应该修改哪个分支。

「高级生图」提供基础文生图、图生图和局部重绘模板。载入模板会替换当前工作流，先保存原预设。可添加 LoRA 并设置模型与 CLIP 权重；复杂分支或自定义节点应在 ComfyUI 中搭好，再导入验证。

底图上传至服务的图片上传接口。无 Bearer 鉴权时可用 WebSocket 观察节点与采样进度；带鉴权时使用轮询取结果，令牌不会放入 WebSocket 地址。

## SDWebUI

1. 服务启用 `--api` 后，填写服务地址。
2. 选择无鉴权、Basic 账号密码或代理 Bearer 令牌。
3. 点击「获取模型与参数列表」，选择 Checkpoint、VAE、采样器等。
4. 填正负提示词、尺寸和采样参数，先文生图测试。
5. 需要 LoRA、高清修复、图生图、蒙版或放大时，再打开对应选项。

接受根地址、`/sdapi/v1/` 和代理前缀；模型留空跟随服务当前模型。列表没有的名称可以手动输入。详细参数、取消和进度边界见 [SDWebUI 原生接入](sdwebui.md)。

## 命名接口与参数预设

| 对象 | 保存内容 | 适合用途 |
| --- | --- | --- |
| 命名接口 | 服务地址、鉴权方式和凭据引用 | 官方、代理 A、代理 B，或不同账号 |
| 参数预设 | 模型、提示词、尺寸、采样与高级参数，可关联命名接口 | 角色立绘、场景、某套工作流 |

推荐顺序：

1. 配好服务后，用命名接口区域的新增按钮保存并命名。
2. 配好绘图参数，在「预设关联接口」选择对应服务。
3. 点击参数预设的「另存为」。
4. 切换时选择预设，再点「载入预设」，确认接口与模型。
5. 修改现有命名接口后点「保存当前接口」；修改参数后点「保存预设」。

预设中的秘钥使用引用保存，不是明文复制到每个参数字段。共享参数包不会分享凭据；跨设备带走秘钥请使用 [加密备份](backup.md)。

## 连接与权限

「生图权限尚未验证」不一定是报错。实际权限需要由一次成功的图片生成确认。若失败，保留具体服务错误信息，再排查 Key 权限、额度、模型、尺寸与服务文档。

接口通常由当前浏览器访问：`127.0.0.1` 指你打开酒馆的电脑，不是远程酒馆主机。HTTPS 酒馆应连接 HTTPS 图片服务，远程接口需允许酒馆站点跨域。不要为解决跨域把私密 Key 放到公开示例里。

## 连接失败时检测设备网络

1. 在发生问题的手机或电脑上打开「接口配置」，点击「测试连接」。
2. 失败后点击「打开调试工具」，选择对应接口并点击「检测当前设备网络」，等待只读检查结束。
3. 点击「复制诊断日志」，手动发给作者；自动复制受限时长按已选中的日志复制，也可以下载 txt。
4. 同时说明代理使用规则模式还是全局模式、换节点后是否复现，避免发送秘钥或私人聊天。

检测只发送 GET 请求，不提交生图、文字生成或工作流。可以停止和重新检测。日志包含版本、设备浏览器信息、脱敏地址、HTTP 状态及耗时，不包含认证头、完整秘钥、响应正文、提示词或聊天，不会自动上传。

0.23.3 起，官方 NAI 的连接测试与诊断订阅检查都使用 `https://image.novelai.net/user/subscription`，与图片请求使用同一官方服务域名。当前接口见 [NovelAI 图片 API 文档](https://image.novelai.net/docs/index.html)。

图片域名首页返回 200，只说明首页访问成功，不等于订阅、秘钥或生图权限通过。401、403、超时和浏览器安全策略会分别提示；浏览器统一的网络错误不足以单独确认 DNS、TLS、代理或跨域原因。不透明辅助响应可能包含重定向，无法读取真实 HTTP 状态或验证鉴权。

在手机本地运行酒馆时，浏览器地址 `127.0.0.1:8000` 是正常情况。只有把生图服务地址也填成手机本机地址，才需要确认该服务是否确实在手机上运行。
