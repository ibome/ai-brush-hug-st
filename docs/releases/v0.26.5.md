# 灵画师 0.26.5

2026-11-03 发布。修复任务历史达到上限后阻止继续生图的问题，自动整理已结束记录与临时响应，并补充直达任务区域的处理入口。

## 生图无需定期清理任务历史

任务记录最多保留最近 100 条。新增任务需要空间时，自动移除最旧的已完成、已关闭或明确被接口拒绝的记录。已保存的图片、聊天配图、历史版本和参数继续保留。

图片保存完成后，临时接口响应会自动释放；旧版本积累的已结束响应也会整理。浏览器清理缓存采用范围删除，减少空事务造成的等待。

正在运行、等待、可继续取图或保存，以及结果待核对的任务仍受保护。插件不会为了腾出位置自动丢弃这些任务，也不会自动重新提交生图请求。

## 需要处理时直接找到任务

若已有 32 个待处理任务，或未保存响应已达到 512 MB，错误旁会显示「查看待处理任务」。

1. 点击按钮，直接打开生图页面并定位到任务区域。
2. 对仍在运行的任务等待完成；已收到图片的任务优先继续取图或保存。
3. 对「结果待核对」先检查接口服务的任务或用量记录，再决定是否关闭或重新提交。
4. 任务区域的垃圾桶只清理已结束记录，已保存图片保留。

这些提示针对任务记录和待保存响应。无需因此重新填写已正常工作的 API，也无需清空图库或整个浏览器站点数据。

## 更新方法

Git 安装在「更新日志 → 版本与更新」或酒馆扩展列表更新，完成后刷新酒馆；ZIP 安装用前端安装包覆盖代码后刷新。

可选服务器组件内部版本更新为 **0.21.2／协议 2**。已安装组件的管理员请下载 `linghuashi-storage-v0.26.5.zip`，等待执行中的任务结束后覆盖组件代码，保留账号数据和 `allowed-accounts.json`，再重启酒馆。普通内置账号存图和浏览器存图用户只需更新前端。

前端兼容旧组件的历史记录上限和临时响应容量错误，只整理可清理的已结束记录，并对同一个任务或同一块响应有限重试；不会重新发送生图请求。更新不清空接口、秘钥、图片或待恢复任务。
